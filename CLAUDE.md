# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

KavziTrader is an LLM-based cryptocurrency trading platform for Binance using a **Brain-Spine Architecture**. The Brain (Scout deterministic filter + Analyst LLM → Trader LLM) handles intelligent market analysis; the Spine handles deterministic, high-speed async execution. Python 3.14+, async-first, event-sourced via Redis Streams.

## Commands

```bash
# Install dependencies
uv sync

# Run all tests
uv run pytest

# Run a single test file
uv run pytest tests/indicators/test_trend.py

# Redis (required runtime dependency)
cd docker && docker compose up -d
```

## Architecture

### Brain-Spine Paradigm

`strategy.active` defaults to `trend_following` (daily Donchian rule in `strategies/trend/`, paper only). The LLM Brain below runs when it is set to `llm_pipeline`; its July 2026 replay lost to buy-and-hold (`evals/README.md`).

**Brain (LLM Layer)** — `kavzi_trader/brain/`
- Scout (deterministic rule filter in `spine/filters/scout.py`, <1ms, no LLM) → Analyst (LLM, `claude-sonnet-5-5` via direct Anthropic API) → Trader (LLM, `claude-opus-5-5` via direct Anthropic API); OpenRouter is a supported per-agent alternative (`provider: openrouter`)
- 90%+ filter rate at Scout before any LLM token is spent
- `brain/config.py`: LLM configuration (per-agent provider, model IDs, effort, retries, API keys)
- `brain/agent/factory.py`: Creates PydanticAI agents for OpenRouter or the direct Anthropic API
- Jinja2-templated prompts in `brain/prompts/`, Pydantic output schemas in `brain/schemas/`
- Env vars: `KT_ANTHROPIC_API_KEY` (provider `anthropic`, the `config/config.yaml` default) or `KT_OPENROUTER_API_KEY` (provider `openrouter`)

**Spine (Execution Layer)** — `kavzi_trader/spine/`
- `execution/`: Order execution engine with staleness validation
- `risk/`: ATR-based dynamic risk validator, volatility calculator, position sizer
- `position/`: Active management — partial exits, time exits
- `state/`: Redis-backed state management (positions, orders, account balance)
- `filters/`: Pre-trade validation chain plus the Scout — liquidity, funding rate, correlation, minimum movement, confluence, Fear & Greed gate, spike cooldown (volatility regime and exposure checks come from `risk/`)

**Orchestrator** — `kavzi_trader/orchestrator/`
- Coordinates 5 core concurrent async loops: DataIngest, OrderFlow, Reasoning, Execution, PositionManagement; optional UiSnapshot and ExternalSentiment loops run alongside
- Latency separation: Brain operates at LLM latency (seconds, bounded by per-agent `timeout_s`); Spine responds in <100ms

**Other modules:**
- `api/binance/`: REST + WebSocket clients (spot, futures, user data streams)
- `indicators/`: Technical analysis (EMA, SMA, RSI, MACD, ATR, Bollinger Bands, OBV, volume analysis, HTF trend)
- `order_flow/`: Funding rate, open interest, liquidation level calculators
- `events/`: Redis Streams event sourcing (immutable audit trail)
- `paper/`: Binance Testnet paper trading mode
- `config/`: YAML + env-based configuration (`config/config.yaml`, `.env`)
- `cli/`: Click-based CLI (`trade`, `model`, `eval`, `ui` command groups and the `config` command)
- `evals/` + `kavzi_trader/evals/`: Eval suite (frozen triple-barrier dataset, paid pipeline runs, signal edge scoring) driven by `kavzitrader eval`; see `evals/README.md`
- `external/`: External sentiment sources (Fear & Greed, DVOL, news) and the LLM synthesizer that summarizes them for the Analyst and Trader prompts
- `ui/`: Real-time WebSocket dashboard (`kavzitrader ui serve`)
- `domain/`, `commons/`, `infra/`: Shared Pydantic domain schemas, utilities (logging, retry, LLM provider enums), and Redis client/config
- `reports/`: Post-session run analysis reports (`report_YYYY_MM_DD.md`). Generated by the `run-analyzer` agent from JSONL logs in `results/logs/`. Each report covers pipeline flow, Scout/Analyst/Trader decision quality, latency metrics, confluence analysis, market validation with post-session outcomes, and prioritized improvement recommendations. Use these reports to understand real-world system behavior and inform code changes.

### Key Data Flow

```
Candle Close → Scout (INTERESTING/SKIP) → Analyst (setup validation) → Trader (trade signal)
  → Pre-trade filters → Risk validation → Execution engine → Binance API
  → Event store (Redis Streams) → Position management loops
```

## Commit Messages

All commit messages must follow this format:

```
[<PART>] <Short message (max 10 words)>
```

Where `<PART>` is a uppercase tag indicating the area of the codebase affected, e.g.: `AI`, `SPINE`, `EVENTS`, `TESTS`, `INDICATORS`, `API`, `CLI`, `CONFIG`, `RISK`, `ORDERS`, `DOCS`, `INFRA`, `REFACTOR`.

Examples:
- `[AI] Add confidence calibration to Scout agent`
- `[TESTS] Cover RSI edge cases for flat markets`
- `[SPINE] Fix trailing stop activation threshold`
- `[EVENTS] Switch Redis stream serialization to msgpack`

Do **not** add `Co-Authored-By` trailers to commit messages.

## Coding Conventions

- **Pydantic only** — no dataclasses. All models use `Schema` postfix (e.g., `TradeOrderSchema`). Use `Annotated[T, Field(...)]` syntax. Instantiate with `model_validate()`, never `**unpacking`. Use `ConfigDict(frozen=True)` for immutability.
- **One class per file** with related helpers allowed. snake_case filenames. DB models use `Model` postfix.
- **pathlib.Path only** — string paths are prohibited.
- **Time variables** must have `_ms` or `_s` suffix indicating units.
- **Logging**: Use `logger.exception()` in exception handlers (not `logger.error()`). Use `%`-style formatting in log messages, not f-strings. Include contextual `extra={}` for structured data.
- **All functions require complete type hints**. mypy strict mode with Pydantic plugin enforced.
- **Absolute imports only** (enforced by ruff TID252, `ban-relative-imports = "all"`).
- **Line length**: 88 chars. 4-space indentation. Ruff for lint + format.
- **No bare tuples** for structured data — use Pydantic models with named fields instead.
- **No `dict[str, Any]`** for fixed-structure data — use TypedDicts (for external API shapes, Redis serialization) or Pydantic models. Plain `dict[K, V]` is fine for genuine dynamic mappings (e.g., `dict[str, Decimal]` for symbol → price lookups).
- **After every change**: Always run `uv run pre-commit run --all-files` and `uv run pytest` after making changes. Pre-commit covers ruff lint/format, mypy and trailing whitespace — use it instead of running ruff/mypy individually. Do not consider a change complete until both pre-commit and tests pass.
